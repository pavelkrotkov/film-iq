# YouTrack Movary watchlist experiment

The installed local app keeps a read-only Movary observation in a separate current-user extension property scoped by project. It does not change Movary, tracker records, watched history, or local POC preferences. Absence is unknown, not an assertion that a film is off the watchlist. The project list only reconciles against visible records and flags unmatched or title-different entries. Preparing an unmatched film fills the Add form but does not create a record or call a provider.

The source observation and its completeness status must be existing private project-local files. `youtrack_watchlist_import.py --snapshot <path>` previews counts; `--apply --backup <new-private-path>` imports after making and verifying an owner-only full-property backup. The owner is bound to the current YouTrack account, but the source snapshot alone does not independently prove which Movary account supplied it. Verify its provenance before importing. The observed source time must not move backwards; a changed observation at the same time is rejected. Source dates with no timezone remain unqualified. Refresh is manual: obtaining a newer complete observation and checking its provenance are separate steps. There is no scheduled refresh.

To recover, `youtrack_watchlist_recovery.py export <new-private-path>` exports the current complete property. Then `youtrack_watchlist_recovery.py restore <backup> --expected <current-export>` previews and `--apply` restores exactly after checking account and current value; readback must match. Both paths must be within a project-local owner-only directory. Stop concurrent writers while importing or recovering: the expected-value guard is not demonstrated to be atomic compare-and-swap.

A pinned YouTrack isolated test used a distinct fictional-only app and user property with the FILMPOC project. Absent initial state, actual project access, fictional import/readback, repeat, stale and changed-value guards, and restore passed. The main app's full watched-property export and visible preferences, settings, and usages matched before and after. Restricted-user denial was checked with fictional in-process users, not a second live account.

The reviewed app was subsequently updated in place. Its downloaded installed package matched the candidate byte for byte. Before importing, the admin user's new property was absent and both project views reported unknown. The complete watched property, visible preferences, app settings, and usages matched before and after the update.

One complete local Movary observation was then imported into the admin user's FILMREAL property. The preview found two entries, neither matching a visible tracker record; exact project and full-property readback passed. The full watched property, visible preferences, app settings, and usages remained unchanged. The snapshot matched the existing single-owner Kaneo watched observation, supporting continuity without independently proving the Movary account identity. No provider, Movary, or tracker-issue write occurred during this update or import. The matching and display behavior has not been checked in a real-film browser walkthrough.

The exact owner-only pre-import property backup is `.cache/tracker-poc/private/youtrack-watchlist-rollout-994a2dfd3f81/watchlist-immediately-before-import.json`; `watchlist-before.json` in the same directory is the earlier matching export, and `watched-before.json` contains the separate full watched-property backup. These contain private data and are not committed. Recovery restores the **whole** watchlist property, including all stored projects; it is not a per-film undo. Real-data restore and complete server recovery have not been exercised.
