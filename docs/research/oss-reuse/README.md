# B6: OSS reuse and license assessment

Version 0.1 · Checked 2026-10-29 · [Issue #16](https://github.com/pavelkrotkov/film-iq/issues/16) · [Epic B](https://github.com/pavelkrotkov/film-iq/issues/2)

This is a source inspection, not an integration benchmark. Code links below pin the inspected revisions. They identify behavior and integration surfaces; no code or source data has been copied into film-iq. The alternatives and effort comparisons are **qualitative**, not measured hours, runtime, accuracy, maintenance cost, or claims of production readiness. Follow [plan.md §11](../../../plan.md), [ADR 0011](../../adr/0011-cost-rights.md), and [ADR 0012](../../adr/0012-empirical-gates.md). Code licenses do not grant rights to source content or provider APIs.

## Candidate decisions

| Candidate | Inspected evidence and provenance fit | Smallest alternative and recommendation |
| --- | --- | --- |
| **GoodWatch** | Its [provider observation logic](https://github.com/alp82/goodwatch-monorepo/blob/79ebfed6a9b06946b82bdcb147f2da41f19e703a/goodwatch-flows/windmill/f/tmdb_api/provider_observations.py) distinguishes omitted countries from explicit empty observations and tracks successful checks. The [provider loader](https://github.com/alp82/goodwatch-monorepo/blob/79ebfed6a9b06946b82bdcb147f2da41f19e703a/goodwatch-flows/windmill/f/main_db/populate/tmdb/providers.py) uses Windmill, ArangoDB and project-specific models. | Use its unknown-versus-empty semantics as a design reference. A narrow Python/SQLite observation record avoids adopting the larger stack; its own correctness and recovery still need tests. **No code copy or dependency proposed.** |
| **Cinemagoria** | The [Cannes endpoint](https://github.com/cinemagoria/cinemagoria/blob/02f8805a0f42d222162804431f3d535cc1a8c0a1/server/api/festival/cannes/films.get.ts#L23-L51) exposes section and source URL but filters records without TMDB IDs. That output alone cannot preserve all unresolved source entries. | Study its section taxonomy, but retain every source entry, including unresolved identities, in a narrow importer. **Do not copy** while repository licensing remains unidentified. |
| **Kometa / letterboxdpy** | Kometa's [Letterboxd conversion](https://github.com/Kometa-Team/Kometa/blob/e1327dc4e7f709277e3e2be88df76c3eefe349e2/modules/letterboxd.py#L880-L926) logs failed TMDB lookups and omits those IDs. [letterboxdpy's list reader](https://github.com/nmcassa/letterboxdpy/blob/a377348f690cb1c94541784c332129a822dbaf59/letterboxdpy/pages/user_list.py#L106-L135) stops when a parsed page contains fewer than 100 items and does not compare the extracted total to its separate source count. Its [page extractor](https://github.com/nmcassa/letterboxdpy/blob/a377348f690cb1c94541784c332129a822dbaf59/letterboxdpy/utils/movies_extractor.py#L113-L145) returns a film-ID-keyed dictionary. These observations establish completeness and lineage risks, not that every list is truncated. | A small parser for a **permitted** source still needs independently audited count, rank/tie, identity and unresolved-entry checks. Do not adopt these Letterboxd paths until the relevant data-access rights are established; see below. |
| **MDBList** | MDBList is a hosted API, not an identified OSS server. Its [API documentation](https://docs.mdblist.com/docs/api) requires a key and reports 1,000 free requests per day and account-wide five-minute limits. Kometa's [client](https://github.com/Kometa-Team/Kometa/blob/e1327dc4e7f709277e3e2be88df76c3eefe349e2/modules/mdblist.py) demonstrates batching and quota error handling; it does not establish independent critical evidence or rights to retain observations. | A narrow HTTP client with bounded requests and explicit failures is the smaller experiment once the provider benchmark and terms justify it. Do not add the service or assert its coverage now. |
| **Critics Lists Aggregator** | The likely project is [padraigfl/critics-lists](https://github.com/padraigfl/critics-lists/blob/04ba9205762818bc45080554c224b6de7f93fa02/README.md), which describes itself as reaggregating Metacritic year-end lists; its [scraper](https://github.com/padraigfl/critics-lists/blob/04ba9205762818bc45080554c224b6de7f93fa02/scripts/metacritic/scrape.js) extracts critics and ranks. Its identification remains provisional because the issue did not specify a repository. The aggregation is derivative, not a new independent vote. | Prefer original critic/list observations and a small rank calculation with explicit source lineage and uncertain identity. **Do not copy** while its licensing is unidentified. |
| **PaperSeek** | Its [evidence module](https://github.com/paperseek/paperseek/blob/e6a53e95925f28f63bea0e23453f212d451782bb/backend/src/paperseek_core/review/evidence.py) preserves run, provider, rank, original abstract and hash; it checks quote locations. For quotes of four or more words its locator can use 80% fuzzy similarity before retaining the actual source span. A located span does not prove correct membership, rank or semantic interpretation. | Use the provenance pattern as a reference, not as proof that film observations are correct. A small source-locator/hash record plus separate completeness and semantic checks fits the narrow requirement. **No code copy or dependency proposed.** |

The narrower alternatives still require validation at trust boundaries, clear failure states, provenance, rights checks and the fixture tests required by the project. They are not a claim that a few lines alone implement those properties.

[Letterboxd's API policy](https://letterboxd.com/api-beta/) says access is by request and is currently not granted for data-analysis, visualization, recommendation, LLM/GPT, private or personal projects, or for recreating paid features. Its [robots file](https://letterboxd.com/robots.txt) also restricts certain crawler user agents and paths. These are separate from the MIT licenses of Kometa and letterboxdpy; neither license gives film-iq Letterboxd data rights. Use only an independently permitted access path, if one is established.

[MDBList's terms](https://mdblist.com/static/legal.html) require compliance with third-party provider terms. The cited terms describe MDBList's own account-data retention; they do **not** establish permission for film-iq to retain or redistribute API observations. Historical retention, attribution and redistribution remain unverified and must be resolved before storing provider data.

## Gate B proposals and open work

1. Keep the initial integration small: adopt the observed unknown-versus-empty and provenance principles, not an entire external application or a new dependency.
2. Require source permission, audited completeness, source-family lineage and unresolved-entry retention before evaluating any list parser as a usable adapter. A successful extraction alone is insufficient.
3. Evaluate MDBList only within the separate provider benchmark and only with valid credentials and confirmed retention rules. Preserve independent source observations and distinguish service evidence from derivative critic data.
4. Do not copy Cinemagoria or the identified critics-list repository absent a verified license or permission. For any later licensed code reuse, audit the exact files and applicable third-party notices before copying.
5. Revisit adoption only with measured extraction accuracy, manual correction time, runtime, operating and dependency cost, failure/recovery behavior and rights. No comparison in this dossier has measured those outcomes.
